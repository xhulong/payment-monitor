# 支付通知监控阶段 E 实施报告

> 完成日期：2026-07-17  
> 分支：`payment-monitor-phase-e`  
> 协议版本：1

## 1. 完成范围

- Flyway V6 新增：
  - 收款二维码资产。
  - 动态金额支付订单。
  - 订单匹配审计。
- 订单金额全部使用整数分存储和比较。
- 待支付订单通过 PostgreSQL 部分唯一索引占用：
  `merchant + platform + payable_amount_minor`。
- 创建订单时在原金额基础上分配 `0–99` 分偏移；冲突时自动尝试下一分值。
- 商户订单号具备幂等创建语义：
  - 相同参数返回已有订单。
  - 参数不一致返回冲突错误。
- 支付订单支持：
  - 等待付款、已支付、已过期、已取消、冲突。
  - 60–3600 秒有效时间。
  - 定时过期扫描。
  - 支付页和二维码 SVG。
  - 人工补单与强制匹配。
  - 完整创建、自动匹配、人工匹配、冲突、取消和过期审计。
- 收入事件入库后按平台、精确金额和订单有效时间窗口自动匹配。
- 同一 `clientEventId` 重试继续返回 duplicate ACK，不重复支付订单或重复写入匹配审计。
- 多候选事件进入 `CONFLICT`，由管理端人工选择订单。

## 2. 管理端

- 新增“收款二维码”页面：
  - 微信/支付宝资产。
  - 启停、编辑、内容模板和二维码预览。
  - 支持 `{amount}`、`{amountMinor}`、`{orderNo}` 占位符。
- 新增“支付订单”页面：
  - 创建动态金额订单。
  - 精确金额、状态、平台和订单号查询。
  - 支付页打开、取消、人工补单。
  - 订单详情和匹配审计。

## 3. 验证结果

- 服务端支付测试：13 项通过。
- 管理端类型检查、lint、生产构建通过。
- Docker Flyway V6 应用成功，四个容器 healthy。
- 实际创建 3 个相同原金额订单：
  - 应付金额分别占用不同分值。
  - 数据库待支付金额唯一。
- 公共支付页、状态 JSON 和二维码 SVG 均返回 HTTP 200。
- 使用 HMAC 设备夹具上传精确收入：
  - 事件 accepted。
  - 订单自动变为 `PAID`。
  - 事件变为 `MATCHED`。
  - 重复上传得到 duplicate ACK。
  - 匹配审计仅产生一次 `AUTO_MATCH`。
- 人工强制补单验证通过。
- 定时过期扫描将测试订单变为 `EXPIRED` 并写入 `EXPIRE` 审计。

## 4. 阶段 F 入口条件

- 订单支付状态已经在数据库事务中可靠落地。
- 下一阶段以订单 `PAID` 为触发点增加事务 Outbox。
- Webhook 投递失败不得回滚或改变已支付订单。
